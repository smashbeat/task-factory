# lot-release pack: implementation plan

**Goal:** a `lot-release` domain pack (supplement batch release package: workbook, CSV, PDFs and email files per lot) built on the shared forge, through to a seed 1 task and a Sonnet screen.

**Spec:** `docs/lot-release-design.md`. **Architecture:** teach the builder that an item can be a folder and that a pack sets its own time limit and scan resolution; lift the coa certificate model and drawing into a forge library both packs import; add three small writers (workbook, CSV, email); add the pack (rules and features as data, model with truth and mutants, three manufacturer sets, reference, tests); build with the existing pipeline.

**Global constraints:** no em dashes in any text that ships; manufacturer, supplier and product names invented; the truth comes from the model and never from reading a file; the coa and size-set packs' outputs must not change (coa seed 4001 build 1k re-renders byte-identical, or pixel- and text-identical on scan routes; the existing 147 tests stay green); every number the policy compares is a `Decimal` in the model and an exact comparison in the verifier; no workbook cell holds a formula.

**Review focus** (inputs the spec implies and no task's tests exercise; each gets its test in the owning task): an email attachment that is not a PDF must be ignored, not crash the reader (Task 6); a workbook cell whose number format is not one the generator uses reads as its stored value (Task 6); a CSV with a byte-order mark and CRLF line endings reads as without (Task 6); an email Date header the parser cannot read must not abort the package, the certificate then counts as undated and never supersedes (Task 6); lot numbers with leading zeros compare as strings after hyphens are dropped, never as integers (Task 4 and Task 6).

## Tasks

### Task 1: builder, items as folders and per-pack limits
- Modify `src/taskfactory/builder/pack.py`: `Domain.seconds: int = 120` and `Domain.scan_dpi: int = 300`, read from `[pack]`. Create `src/taskfactory/builder/items.py` with `copy_item(src: Path, dst: Path) -> None` (file or tree) and `item_size(path: Path) -> int`. Use them in `assemble.py`, `docker.py` (the reference stage's input copy) and `agent.py` (the fix workspace). `render_main.py` makes no assumption about the item being a file: it passes the path and reports `item_size`. `reference_main.py` takes the limit as a sixth argument (default 120); `docker.reference` passes `pack.seconds`; `build.py` passes `pack.seconds` to `reference_gate(limit=...)`. `docforge.finish` and `rasterize` take `dpi` (default 300) and the scan routes use it.
- Interfaces produced: `copy_item`, `item_size`, `Domain.seconds`, `Domain.scan_dpi`, `finish(route, base, path, rnd, meta, size, wrong_base=None, dpi=300)`.
- Test `tests/test_items.py`: `copy_item` copies a file and a directory tree; `load_domain` on coa gives `seconds == 120` and `scan_dpi == 300`; a temporary pack.toml with `seconds = 300` loads them. Run the whole suite: 147 pass.
- Commit.

- Test `tests/test_office.py`: a written workbook read back with openpyxl (`data_only=True`) gives the stored values, the number formats, the hidden rows and the hidden sheet, the merged range and a `datetime` for a date cell; a CSV written with semicolons and decimal commas and dot thousands reads back line by line, and one with a BOM starts with it; an `.eml` parsed with the standard library decodes its attachments to the same bytes, parses its Date with the zone, carries `In-Reply-To`, and a forwarded one holds a `message/rfc822` part whose attachment decodes.
